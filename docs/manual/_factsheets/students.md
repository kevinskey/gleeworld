## GleeWorld — Student Experience Fact Sheet

Scope: how a signed-in student finds music/resources, records with Part Tracks & Studio, submits assignments, and checks in for attendance. All references are to files under the repo root. Every claim below was read in code.

### 0. Navigation & access model (how students reach these features)

- The left navigation is the **My Tools shelf** (`src/components/dashboard/NavShelf.tsx`, rendered by `DashboardShell`'s desktop sidebar and mobile drawer): Home, then up to 8 destinations the student chose, flat — no groups, no accordions. Everything else in the catalog sits behind the **All Tools** disclosure below it, grouped by section. The same 8 destinations render as the keycap grid on `/dashboard` (`HomeTileGrid`), so shelf and grid always show the same set.
  - The destinations themselves come from one catalog, `src/lib/navigation/navCatalog.ts` (`NAV_CATALOG`) — e.g. "Music Library" → `/dashboard/music-library`, "Part Tracks" → `/dashboard/part-tracks`, "Studio" → `/studio`, "Academy" → `/dashboard/academy`, "Videos" → `/video`. Each entry carries its own gate (module / admin / librarian / partner), applied by `resolveNav`.
  - A student's chosen set lives in `user_preferences.nav_item_order` as a v4 `MyTools` record (`src/lib/navigation/myTools.ts`); with no record they get `DEFAULT_TOOLS_STUDENT`. On phones the docked bottom tab bar (`MobileBottomNav`) carries Home/Messages/Calendar instead.
  - The older `AppNavigation.tsx` group taxonomy was deleted on this branch; nothing renders from it now.
- All the student tool routes are wrapped in `ProtectedRoute` (`src/App.tsx:408-452`), which only requires being logged in: unauthenticated users are redirected to `/auth`; users with `must_change_password` are sent to `/force-password-change`; otherwise the page renders behind `ProfileCompletionGuard`. There is **no per-plan/entitlement gate on these individual routes** — the routes themselves only check auth.
- Feature availability by tenant is controlled at the module/tile level via `useTenantModules`/`useModuleAccess` (`src/hooks/useModuleAccess.ts:21-50`), which reads the `v_tenant_active_modules` view. Modules have a `tier` of `starter | addon | enterprise` and a `status` of `starter | active | trial | past_due | cancelled`. Module definitions live in `src/config/unified-modules.ts` (e.g. `music-library` at :85-96, `part-tracks` at :97-108, `attendance` at :138-149, `glee-academy` at :423-424).

### 1. Finding music & resources — Music Library

Primary page: `src/pages/dashboard/MusicLibrary Page.tsx` (route `/dashboard/music-library`; also linked as `/music-library`). It shows sheet-music scores only from `gw_sheet_music` (`MusicLibraryPage.tsx:100-105`).

- Three top tabs (`MusicLibraryPage.tsx:143-146`): **Scores**, **Setlists**, **Public Domain**.
- Scores tab: a **Scope** filter (chips) plus a search box that filters by title/composer/voicing (`MusicLibraryPage.tsx:118-126, 167-184`). Each score renders as a card (`ScoreCard`, :373-480) showing title, composer, a rights badge, voicing/difficulty badges, course code or "Platform" badge, an "Audio" badge if a recording is attached, and physical-copy count/location.
- Clicking a score card (when it has a PDF) opens a near-fullscreen annotated PDF viewer (`PDFViewerWithAnnotations`) via the **Annotate** action; annotations persist in `gw_sheet_music_annotations` (`MusicLibraryPage.tsx:38-40, 211, 270-366`, header comment :1-6).
- **The Music Library is read-only for browsing/playback for students.** Upload/URL import and the "Attach audio" / "Edit score" dialogs are gated by `canEditMusicLibrary()` (`MusicLibraryPage.tsx:74-75, 137-138, 444-465`). Header comment at :137-139 states score upload lives in the Librarian add-on.
- Audio companion: scores can have one or many audio tracks (`gw_sheet_music_audio_tracks`), of kind file / media_library / youtube / apple_music, one marked default which auto-loads (`AttachAudioDialog`, :483-989). Apple Music playback requires an active subscription; free users get a subscription prompt at play (:844-846).
- Setlists tab wraps `SetlistBuilder` for building/playing performance orderings (`MusicLibraryPage.tsx:221-244`). Public Domain tab is a CPDL search (`PublicDomainSearch`, :246).
- Course-scoped resources for Academy courses render via `src/components/academy/CourseLibrarySection.tsx` (adopt-a-course store — admin-facing, gated on the `COURSE_STORE` feature flag, :21,40) and `CourseResourcesList.tsx` / `ModuleResources.tsx` (not fully read here).

### 2. Part Tracks — TWO distinct experiences (important to disambiguate)

There are two separate "Part Tracks" surfaces backed by different code:

**(A) Part Tracks Studio** — route `/dashboard/part-tracks` (and `/dashboard/part-tracks/:projectId`). Landing page: `src/pages/dashboard/PartTracksLandingPage.tsx`; studio: `src/components/partTracks/PartTracksStudio.tsx` (~2,595 lines). This is a full multitrack recording environment.
  - Every project must be linked to a score in the Music Library — there is no path to record without a score (`PartTracksLandingPage.tsx:1-3`). "New Project" opens a dialog: step 1 pick a score from `gw_sheet_music` (search), step 2 set project title + voicing (SATB/SSA/etc via `VOICING_TEMPLATES`), which seeds the track list (`PartTracksLandingPage.tsx:185-322`; "SATB → S/A/T/B, SSA → S1/S2/A" at :319-321).
  - Projects are stored in `gw_part_tracks_projects` and listed as cards showing voicing, tempo, key signature, created date; cards can be deleted with a toast confirm (`PartTracksLandingPage.tsx:48-172`).
  - Studio layout is 3-column on desktop / stacked on phone (`PartTracksStudio.tsx:1741`): left = **Accompaniment** (choose/change backing track) + **Voice parts** roster; center = **Multitrack** timeline with zoom (1×–8×) and a time readout; right/Tools = Devices, Recording, Audio tools, Practice tracks (`PartTracksStudio.tsx:1744-1844, 2104, 2297, 2308`).
  - Backing track sources: file, Apple Music (song or album), or YouTube; external sources stream alongside the mix but only the mic is captured into recordings (`PartTracksStudio.tsx:1744-1782`, `AccompanimentPicker.tsx`).
  - Recording is a two-step DAW flow: arm a track with its per-row mic icon, then press the transport **Record** (`PartTracksStudio.tsx:89-96, 2069-2091`; disabled until a track is armed). Transport = Stop / Play(amber) / Record; extra recording controls: count-in (0/4/8/2 clicks toggle), punch-in `[I]` / punch-out `[O]` markers (`PartTracksStudio.tsx:2049-2091, 2012-2046`).
  - Per-take **Audio tools**: Trim silence, Even volume (normalize), Cut hum + hiss (noise reduce), and nudge take 0.1s Earlier/Later, Clear (`PartTracksStudio.tsx:2179-2220`, imports `trimSilence, normalize, reduceNoise` at :51).
  - Track kinds/colors: Soprano, Alto, Tenor, Bass, Solo, Piano, Custom Track (`PartTracksStudio.tsx:73-81`). "Wear headphones" bleed warning is shown once per session (:59, :1992).

**(B) Part Tracks module tile** — the dashboard module `part-tracks` (`unified-modules.ts:97-108`, title "Part Tracks", description "Upload MP3 practice tracks per voice part on each piece") renders `src/components/modules/PartTracksModule.tsx`, a simpler per-piece MP3 upload/record grid. It uses `RecordModal` (`src/components/part-tracks/RecordModal.tsx`) and `PartMixer` (`src/components/part-tracks/PartMixer.tsx`). Parts are free-text with presets SI/SII/AI/… plus accompaniment presets (`PartTracksModule.tsx:43-49`). Each part row can be soloed/muted in the mixer; a "Play all" plays the piece (`PartTracksModule.tsx:40-48, 76-77`).

**RecordModal recording flow** (`RecordModal.tsx`, used by (B)): idle → count-in → recording → encoding → preview → save. Details:
  - Max 10 minutes; mic permission required; headphones recommended (`RecordModal.tsx:10, 445-447`).
  - Audio device pickers for mic input and output; Safari falls back to system default for output routing (`RecordModal.tsx:459-500`).
  - "Hear other parts while recording" monitor mix: plays existing parts through the chosen output when recording starts, with an on/off toggle and a monitor-volume slider (`RecordModal.tsx:502-549`).
  - Click track settings persisted in localStorage (`gw_part_tracks_click_settings_v1`): tempo BPM (40-240), time signature (2/4, 3/4, 4/4, 6/8), count-in measures (None/1/2), "keep clicking while I sing" (`RecordModal.tsx:14-49, 552-603`).
  - Recording deliberately disables echoCancellation/noiseSuppression/autoGainControl for flat music capture (`RecordModal.tsx:236-245`). Output is encoded to a 128 kbps MP3 via a worker (`RecordModal.tsx:354-397`). Preview player, then Re-record or Save MP3 (`RecordModal.tsx:653-682`).

### 3. Studio — general multitrack DAW

Routes: `/studio` (session list) and `/studio/sessions/:id` (editor). Files: `src/pages/studio/StudioHome.tsx`, `src/pages/studio/StudioEditor.tsx` (~5,370 lines), `src/pages/studio/MixerView.tsx`.

- StudioHome lists the student's sessions ("Sessions sync across your devices"), with a **New session** dialog (optional title) that creates a session and navigates into it (`StudioHome.tsx:20-67, 130-153`). Each session card shows track count, duration, updated date, and a delete (confirm) button (`StudioHome.tsx:85-124`). Backed by `useMySessions`/`useCreateStudioSession`/`useDeleteStudioSession`/`useStudioOwner` from `src/hooks/useStudio.ts`.
- StudioEditor is a fuller DAW than Part Tracks. Confirmed UI affordances (from labels/titles in `StudioEditor.tsx`): per-track **Arm for recording** (:4316), record/click/metronome, **Count-in bars** (:1748), Tempo (BPM) and **Time signature** (:1638, :1643), **Undo** (:1755), markers ("Add marker at playhead (K)" :1552, Edit marker :2110), **Snap to beat / Snap to bar** and **Time stretch** (:3361, :3371, :3399), clip select/deselect/resize, **Track color** (:3262), **Volume** (:3189), **Smart Controls** (:5005), **Inspector** panel (:4625), and an **Import audio** dialog (:2950). Export/Download dialog offers **Stereo mix / Mono stems / Individual files** with a **Destination** of **Download** or **Media Library** (:3615-3674, :3637-3646). **Audio settings** cover output device selection, a **Test output**, and **Recording latency compensation** (:5198-5275). A "Download session JSON" option exists (:1411).

### 4. Practice Studio (assignments + record)

Route `/practice-studio` → `src/pages/PracticeStudioPage.tsx` → `src/components/practice-studio/PracticeStudioDashboard.tsx`. Three views: **assignments**, **practice**, **record** (`PracticeStudioDashboard.tsx:37`). Pulls assignments/submissions from `useAssignments` (`:26-34`) and computes per-assignment status (not_started / in_progress / submitted / completed, `:42-48`). Overdue and next-7-days upcoming lists are shown (`:39-40`). Uses `AssignmentViewer` and `RecordingStudio` (`:19-20`). Related course-scoped recordings tab: `src/components/academy/CoursePracticeTab.tsx` — students see only their own takes (RLS), teachers see the whole roster and can leave feedback; recordings live in `gw_practice_recordings` (`CoursePracticeTab.tsx:45-98`). The empty-state tells students new recordings come from "Music Tools → Metronome → Record practice" (`CoursePracticeTab.tsx:126-130`).

### 5. Assignments & submissions (Grading / Academy)

- Student-facing grading routes (`src/App.tsx:376-378`): `/grading/student/course/:course_id` (`StudentCoursePage`), `/grading/student/assignment/:assignment_id` (`StudentAssignmentPage`), plus a `StudentDashboard`.
- Course view for a student: `src/components/grading/student/StudentCourseView.tsx`. Header shows a combined **Grade & Attendance** hero (letter grade + %, or "Attendance-based" for attendance-only courses like MUS 070) (`StudentCourseView.tsx:224-303`). Tabs: **Grades**, **Work** (assignments; hidden for attendance-only courses), **Polls** (`:304-320`).
  - Grades tab has two models: an attendance-only model (allowed absences, unexcused-absence count, one-letter-drop-per-excess policy, schedule-conflict card, excuse form) and a standard deductive model (syllabus weights, assignment/attendance deductions, quick stats) (`StudentCourseView.tsx:324-508`). Grade colors by percentage (`:172-178`).
  - Assignments (Work) tab lists published assignments from `gw_course_assignments` (`is_published = true`) joined with the student's submission status from `gw_assignment_submissions`; polls every 30s for instructor changes (`StudentCourseView.tsx:64-92`). Each assignment card shows title, due date, points (or awarded/total once graded), instructor feedback, and a **View** button → `/grading/student/assignment/:id` (`:515-561`). Released grades come from `gw_grades` where `released_to_student = true` (`:94-106`).
- Assignment detail / submission: `src/components/grading/student/StudentAssignmentView.tsx`. Loads the assignment from `gw_course_assignments` (`:44-57`). The assignment is treated as a **video** type if `assignment_type === 'exercise'` or title contains "conducting"/"video" (`:60-62`).
  - Video-type assignments submit a recording via `VideoRecordingSubmission` into `gw_assignment_submissions` (fields `recording_url`, `notes`, `status='submitted'`, `submitted_at`) (`:107-124, 218-230`).
  - Essay/general assignments submit free text into `gw_course_submissions` (fields `content`, `word_count`, `status='submitted'`) with a Textarea and **Submit** button; existing submissions can be edited via **Edit → Update Notes** unless status is `ai_graded`/`revision_submitted` (`:126-159, 232-300`).
  - Submission status badges: `submitted`, `graded`, plus special "Graded — Revision Available" (`ai_graded`) and "Revision Submitted" (`revision_submitted`) (`:189-202`). If `ai_feedback` is present, an `AIFeedbackRevisionCard` renders for revision (`:304-313`).
- Sight-reading assignments have a dedicated `src/components/sight-reading/AssignmentSubmissionModal.tsx` (submission table note in `StudentAssignmentView.tsx:96-98`: `gw_assignment_submissions.assignment_id` references `gw_sight_reading_assignments`).

### 6. Attendance check-in (student side)

Three student check-in paths, all requiring login:

- **QR scan (deep link from instructor QR).** Route `/attendance/scan` (and `/attendance-scan`) → `src/pages/AttendanceScanPage.tsx`. Reads a `token` from the URL, and if the user is logged in, calls RPC `process_qr_attendance_scan(p_qr_token, p_user_id, p_user_agent)` (`AttendanceScanPage.tsx:56-77`). On success it toasts "Attendance Recorded!" and auto-redirects (~1.2s) to the mapped course home (course-id → route map at `:22-30`) or `/dashboard?module=glee-academy` (`:102-116`). If not logged in it shows "Login Required" and stores a redirect-after-auth path (`:136-168`); invalid/missing token shows "Invalid QR Code" (`:170-194`).
- **Camera QR scanner.** Route `/qr-scanner` → `src/pages/QRScanner.tsx` using `QRAttendanceScanner`. If a `token` is in the URL it auto-processes via RPC `process_qr_checkout_scan(...)` (note: checkout variant) and interprets `result.checkout` / `result.status === 'in_rehearsal'` to toast "Attendance Confirmed" vs "Checked In — In Rehearsal" vs "Attendance Recorded"; on the in-rehearsal state it tells the student to scan the checkout QR at end of class (`QRScanner.tsx:37-93, 63-74`). Without a token it renders the live camera scanner (`:143-155`). This implies a two-scan (check-in then checkout) model for some sessions.
- **PIN entry.** Route `/attendance/pin` → `src/pages/AttendancePinPage.tsx` → `src/components/attendance/PinAttendanceEntry.tsx`. Student enters a **6-digit code shown by the instructor** across 6 auto-advancing boxes (paste supported); auto-submits when full (`PinAttendanceEntry.tsx:56-91, 195-220`). It attempts to capture geolocation for geofencing (best-effort, 5s timeout), then calls RPC `process_pin_attendance_scan(pin_code_param, user_id_param, scan_location_param)` (`:112-134`). Success shows "Attendance Recorded!" with event details and haptic feedback; failure shows the error and "Try Again" (`:139-169, 260-312`). The PIN page also offers a button to switch to the QR scanner (`AttendancePinPage.tsx:42-53`).

- **Attendance history / self-service.** `src/components/attendance/MyAttendance.tsx` reads the student's own records from `gw_event_attendance` joined to `gw_events` (`MyAttendance.tsx:97-115`). Period selector: This Month / Last Month / This Semester / All Time (`:186-196`). Shows an attendance-% donut (present+late over total, `:117-124`), stat tiles (Present/Absent/Excused/Late), a month calendar heatmap keyed by status color, recent records list, and embeds `MyExcuseRequests` + `ExcuseGenerator` for excuse requests (`:163-364`). Statuses used: present, absent, excused, late, left_early (`:49-55`).
- Within a course, students also see their attendance inline in `StudentCourseView` (from `gw_event_attendance` over the course calendar's events) and can request an **Excuse** on any absent session via the `RehearsalConflictForm` (`StudentCourseView.tsx:108-150, 280-291, 418-421`).
