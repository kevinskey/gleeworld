The three things you reported

1. "I couldn't close out an invoice" Fixed

Confirmed. Three separate gaps combined into this:

  • Drafts could not take money. The server treats a draft as "not a bill yet", so the list hid the Record Payment button on every draft. Cash taken before the bill was sent had nowhere to go. Desktop and phone disagreed (the phone card did show it).
  • No Close / Void / Archive anywhere on the Invoices screen. The archive route existed on the server but the only UI for it was a menu on the dashboard pipeline, which never listed drafts. The only exits were Delete (irreversible) or leaving it forever.
  • "Save & Mark Paid" used a browser prompt() to ask how they paid. On iOS and inside the app wrapper that dialog is blocked, so the button appeared to do nothing.

Now: every unpaid row, drafts included, has a green Mark paid (or Collect balance) button that opens a modal with Cash / Zelle / Cash App / Card / Check chips, amount pre-filled to what is due, and a Mark Paid in Full confirm. Every row and the editor have Close out (paid) / Void (unpaid) which archives without deleting; the list has Partial and Archived filters. All browser dialogs on the invoice screen were replaced with in-app confirms. A partially paid invoice no longer flips back to "sent" when you resend the balance.

2. "Product pictures and information are truncated when adding to a quote" Fixed

Confirmed in two places. The type-ahead under the Product box was an absolutely positioned list inside a scrolling drawer, so it was clipped at the drawer edge, and inside the Send Price modal (capped at 512px wide) it was cut to two half rows with 32px thumbnails and names ending in "…". The Browse button also searched the catalog for the line's full product name ("Gildan Heavy Cotton T-Shirt") and found nothing.

Now: suggestions render in a floating layer above everything (it follows scrolling and flips up when there is no room below), 440px+ wide, with 56px photos, names on two lines, brand · style · category, and retail / blank price. The Send Price modal widens when the line-item editor is open. Browse opens with an empty search when the line already has a product. The invoice editor's own line-item type-ahead got the same photo/brand/price treatment.

3. "I should be able to just send a bill to a customer on the spot" Fixed · new

Before: the shortest path to bill a walk-in $45 was Invoices → New → name → email → description → qty → price → Preview & Send → Save & Mark Paid → browser prompt. Nine to ten clicks, and the defaults were wrong for a counter sale: 7.75% tax auto-applied ($45 became $48.49) and "Require 50% deposit" was on, so an emailed link asked for $24.25.

Now there is a Quick bill button on the dashboard Quick Actions and in the Invoices header:

Who
Name (finds past customers as you type and fills email + phone), email, mobile. Email or phone is enough.
What for
Description · qty · price each. More lines if needed. Tax off unless you tick it. No deposit.
Then one of three
Email pay link · Text pay link · They paid just now (Cash / Zelle / Cash App / Card / Check → Mark paid & email receipt).

Every quick bill becomes a normal invoice with an order number (TSB-n), so the invoice list, the order page and the customer page all see it. If the email or text fails at the provider, the modal says the bill is saved and offers Open the invoice / Retry / Keep as draft. A phone-only customer gets Text + Mark paid (the database now allows an invoice without an email).

Still open

Worth doing, not done here. Each is a larger change or a judgement call about how you want the shop to run.

  • Send Price modal prices one size grid for the whole quote. A second product added inside the modal is folded into the first product's S/M/L/XL rows with no label. Pricing per line needs the pricing form reworked around quote_items. Open
  • No admin "New quote". Quotes can only be started from the public quote pages; the admin path is Invoices → New (or now Quick bill). An admin-side "New quote for a walk-in" would close that gap. Open
  • Customer account page labels a pending quote "Quoted: $432" (the auto-estimate), has no Accept / Pay deposit action on a priced quote, no invoices list, and loses the ?redirect on login. Open
  • Easy Quote wizard stores color, print location and quality only in free-text notes (not on quote_items), never states the deposit amount on "Accept & Pay Deposit", and the confirmation has no "what happens next" or tracking link. Open
  • Mobile admin layout: the order page stepper needs horizontal scroll inside its card; the new-invoice line-item row is cramped at 390px; the Products section scrolls sideways. Open
  • Raw error text reaches customers in development (e.g. "getaddrinfo ENOTFOUND" on art upload). Production's error middleware masks server errors, but the Stripe SDK message on the invoice page's Pay Now still shows verbatim. Open
  • Quote status badge stays "Accepted" on orders paid in full. Open
  • Quotes list hides "Convert to Invoice" once an invoice exists and shows an invoice chip instead; the chip opens the invoice silently. Works, but worth a word on the row. Open

Test environment notes Environment

  • Stripe, Resend (email), Twilio (SMS) and DigitalOcean Spaces (uploads) were placeholder keys, so every provider call failed. Those failures are not app bugs; how the UI handled them is reported above.
  • The database was rebuilt from the repo's migrations plus a hand-written bootstrap for the tables production created by hand (invoices, quote_items, promotions, saved_designs, gang_sheets). Consider committing a baseline schema so a fresh clone can boot.
  • One repo migration, jds_price_tiers.sql, fails on Postgres 16 ("cannot use subquery in check constraint") and is retried on every boot.
